Design Section 2 of 5: Conversation State Machine

Every WhatsApp conversation passes through these states in order

1. GREETING
AI sends welcome message
↓
2. COLLECTING
Collect: Name · Company · Address · Product
⚠ Rules engine runs on every message
↓ all 4 fields collected
3. CLARIFYING
Ask about ambiguous specs: color, size, qty, location
Max 3 clarification rounds, then proceed
↓ specs clear
4. STOCK_CHECK
Query stock_items in DB · check price · check availability
AI presents: items, price, total
↓ customer reviews summary
5. CONFIRMING
Awaiting customer reply: "OK" / "BENAR"
Any other reply → AI re-explains or goes back to CLARIFYING
↓ "OK" / "BENAR" detected
6. BOOKED ✓
Order locked · stock reserved · 2×24hr timer starts
→ order row pushed to Dashboard as PENDING
↓ timer running
7a. TIMEOUT_REMINDER
At 44 hrs · WA reminder sent
in customer's language
↓ no reply by 48 hrs
8a. CANCELLED
Stock released · admin notified
7b. APPROVED
Admin inputs shipping fee
clicks Approve in Dashboard
↓
8b. COMPLETED ✓
WA invoice blast sent
with bank transfer details

Escalation exits — can fire from COLLECTING, CLARIFYING, or STOCK_CHECK

⚡ ESCALATED_WIRING
Triggered by keywords (rules engine):
"instalasi", "grounding", "panel custom", "wiring", "proyek besar", "diagram"

Action: AI sends: "Permintaan ini membutuhkan tim teknis kami. Staf kami akan segera menghubungi Anda." → chat appears in Sales Inbox as WIRING_CUSTOM
🚨 ESCALATED_ADMIN
Triggered by rules:
Product not in DB after 2 attempts · customer requests discount · offensive language

Triggered by LLM:
Returns next_action: "ESCALATE" when it can't resolve ambiguity

Action: AI sends polite handover message → chat flagged BUTUH_ADMIN in Sales Inbox

What Gemini does at each state

State Gemini's job Structured output fields
GREETING Detect language · generate warm greeting reply, detected_language
COLLECTING Extract fields from message · ask for next missing field reply, collected{name,company,address,product}, next_action
CLARIFYING Ask one clarifying question · extract specs from answer reply, specs{qty,size,color,notes}, next_action, clarification_round
STOCK_CHECK Format order summary with DB data · present price reply (includes price/stock), next_action
CONFIRMING Detect OK/BENAR · handle modifications · re-explain if needed reply, confirmed: bool, modification_requested: bool
