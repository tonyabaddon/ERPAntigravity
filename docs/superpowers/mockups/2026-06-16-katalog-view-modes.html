Mockup Review — Katalog: 3 Mode Tampilan

2026-06-16 • Design system mengikuti ERPAntigravity. Pain point: foto dominan bikin susah scan SKU/harga/stok

Problem Switcher A. Foto B. List C. Padat Lightbox
help

Problem yang dipecahkan

Tampilan Katalog sekarang (mode Foto) bagus untuk browsing visual, tapi susah cari barang spesifik:

  • Terlalu sedikit produk per layar — foto besar makan tempat, harus scroll panjang untuk lewatin 50 SKU.
  • Susah baca SKU/nama/harga — teks kecil di bawah foto, kontras foto bikin mata jump-around.
  • Bandingin harga/stok antar produk butuh klik satu-satu — tidak ada tampilan tabular yang bisa di-skim seperti spreadsheet.
  • Cari by SKU/nama via keyboard, foto cuma distract — toko sudah tahu produknya, butuh konfirmasi cepat harga + stok per gudang.

Solusi: tetap pakai mode Foto sebagai default (visual identity), tambahkan 2 mode alternatif yang bisa di-switch dengan 1 klik: List (tabular, dominan teks, foto jadi thumbnail kecil yang bisa di-klik untuk lightbox) dan Padat (grid kompak, foto kecil + teks lebih dominan, ~3x lebih padat dari mode Foto).

Pertanyaan untuk dijawab sebelum implementasi

  1. Default mode per user — Foto, atau remember mode terakhir? (Saran: remember mode terakhir per-user via localStorage, fallback ke Foto untuk first-time)
  2. Stok per gudang di mode List — tampilin semua gudang sebagai kolom (bisa 3-5 kolom kalau toko punya banyak gudang), atau cuma 2 + dropdown "lihat semua"?
  3. Klik foto thumb di mode List — default: lightbox modal. Cmd+klik / middle-klik = tab baru. Apakah perlu opsi setting "always open new tab"?
  4. Mode "Padat" perlu atau di-skip? — kalau List sudah cukup, kita bisa drop ke 2 mode saja (Foto vs List) supaya UI lebih simpel.
  5. Apakah mode-switch ini scope tambahan untuk spec product-photo-search yang sudah approved, atau spec terpisah?
