Tujuan Mockup

Visualisasi UI fitur diskon manual sebelum implementation. Cakup: Pengaturan (3 toggle), Kasir cart + total bar, Wizard Step 2 + 3, Tagihan PI form, Invoice PDF render, Pengawasan view. Fokus pertanyaan review:

  • Apakah bidirectional Harga ↔ Diskon (default AMOUNT) intuitif untuk kasir?
  • Apakah label "List Rp …" di atas Harga membantu, atau ribut?
  • Apakah 3 toggle di ModulSwitchesPanel cukup, atau perlu panel dedikasi?
  • Layout baris "Diskon" di PDF invoice — posisi & format OK?
  • Ada UX yang menurut Anda misleading / akan disalahgunakan kasir?

UX Notes (highlighted rows):
Path A = user ketik di kolom Diskon; toggle %/Rp. Harga auto-update.
Path B = user ketik di kolom Harga (UX kasir lama, dipertahankan). Diskon auto-fill ke AMOUNT, format toggle reset ke "Rp".
Label kecil "List Rp …" di atas Harga = snapshot master price saat item ditambah. Tidak ikut berubah meskipun harga master diupdate di kemudian hari (fix latent bug `v_pengawasan_kasir_discount_7d`).
Markup (Harga > List) → border merah + tombol Simpan disabled, error MARKUP_NOT_ALLOWED.
Cara ubah Diskon Rp ↔ %:
Klik segment yang ingin diaktifkan di pill toggle: → klik % →
Konversi otomatis & equivalent: nilai diskon ikut dikonversi supaya hasil Rupiah sama.
  • Contoh: input Rp 20.000 di line MCB qty 2 (List Rp 80.000 × 2 = 160.000). Klik % → input berubah ke 12.5% (= 20.000 / 160.000). Subtotal tetap Rp 140.000.
  • Sebaliknya: input 10%. Klik Rp → input berubah ke nilai Rp absolut equivalent. Subtotal tetap.
Catatan: kolom Subtotal & Total tidak berubah saat toggle. Field discount_amount_rp yang disimpan ke database juga sama. Yang berubah cuma representasi yang ditampilkan (raw input + type).

Frame 7 / 8 — Pengawasan Kasir Diskon 7 Hari (view rewrite)

Pengawasan · Diskon Kasir (7 hari terakhir)

Sumber: v_pengawasan_kasir_discount_7d (rewritten — sum explicit discount_amount_rp)

Kasir Revenue 7d Diskon 7d % Diskon Action
Tono Rp 12.430.000 Rp 145.000 1.17% Detail →
Siti Rp 8.910.000 Rp 420.000 4.71% Detail →
Budi Rp 6.200.000 Rp 1.180.000 19.03% ⚠ Review →
Yang berubah: view lama derive diskon dari stocks.price − kti.unit_price (current price). Bug: kalau owner ubah harga master, "diskon" historis ikut bergeser. View baru baca explicit discount_amount_rp dari JSONB items + kolom top-level. Snapshot stabil.
Atribusi order-level discount: dijumlah utuh ke cashier (tidak di-prorate ke per-line). Sederhana dan defensible.
Trade-off accepted: founder pilih tanpa cap %. Mitigasi = pengawasan retrospective ini. Kasir Budi 19% → owner reach-out manual.
Frame 8 / 8 — Review Checklist

Apa yang perlu di-validasi sebelum lanjut implementation plan

UX
  • ☐ Bidirectional Harga ↔ Diskon intuitif untuk kasir?
  • ☐ Label "List Rp …" di atas Harga membantu, atau ribut?
  • ☐ Toggle %/Rp posisi di kanan input OK?
  • ☐ Highlight orange untuk row dengan diskon — terlalu loud?
  • ☐ Markup ditolak hard — pengaruh ke alur kasir lapangan?
Settings & Scope
  • ☐ 3 toggle di ModulSwitchesPanel cukup?
  • ☐ Default semua ON OK?
  • ☐ Apakah perlu juga toggle di PO (Purchase Order), bukan cuma Tagihan?
PDF / Invoice
  • ☐ Baris "Diskon" warna orange — terlalu mencolok di customer print?
  • ☐ Line-level discount disembunyikan (baked ke Harga column) — atau perlu kolom "Diskon" terpisah?
  • ☐ Format "Diskon Order (5%)" vs "Diskon Order" tanpa %?
Akuntansi & Audit
  • ☐ Akun 5-1900 Diskon Pembelian (seed baru) — nama OK?
  • ☐ View pengawasan threshold warna (green <2%, yellow <10%, red ≥10%) — angka cocok?
  • ☐ Tanpa cap %, tanpa PIN — masih oke untuk go-live?
