# Stock Manager — Product Specs Enhancement Design

**Date:** 2026-06-04  
**Status:** Approved — Ready for Implementation

---

## Problem

The current `stocks` table only stores (sku, name, category, price, stock, status). Calista's AI conversations ask customers about product specs (material, dimensions for Panel; merek/ampere/phase for MCB; tipe/mm²/panjang for Kabel), but this data doesn't exist in the database. Stock searches rely on free-text `name` matching, so structured specs can't be queried or surfaced to customers.

---

## Solution

Add a `specs JSONB` column to the `stocks` table. SKU becomes auto-generated by the database. Product `name` is auto-generated from spec fields by the frontend (no manual entry). The Stock Manager UI gets dynamic per-category spec forms, inline editing, and a rebuilt CSV bulk upload template.

---

## Database (Supabase Migration)

New migration: `20260604000001_stocks_add_specs.sql`

```sql
ALTER TABLE public.stocks
  ADD COLUMN IF NOT EXISTS specs JSONB NOT NULL DEFAULT '{}';

ALTER TABLE public.stocks
  ALTER COLUMN sku SET DEFAULT gen_random_uuid()::text;
```

- `specs JSONB` stores category-specific fields as key-value pairs.
- `sku DEFAULT gen_random_uuid()::text` — new rows get a UUID-based SKU automatically; existing rows are unchanged.

## Category Spec Fields

| Category | Spec Keys |
|---|---|
| Panel | material, tipe_pasang, tinggi_cm, lebar_cm, tebal_cm, ketebalan_mm, finishing, kelengkapan |
| MCB | mcb_merek, mcb_ampere, mcb_phase |
| Kabel | kabel_tipe, kabel_mm2, kabel_panjang |
| Aksesori | deskripsi |

### Field options

**Panel:**
- `material`: Besi / Stainless SS304 / Stainless SS316 / Aluminium / PVC
- `tipe_pasang`: Indoor / Outdoor
- `ketebalan_mm`: 1 / 1.2 / 1.5 / 1.8 / 2 / 3
- `finishing`: RAL7032 / Warna Khusus
- `kelengkapan`: Kosong / Dengan Komponen + Rakit
- `tinggi_cm`, `lebar_cm`, `tebal_cm`: numeric (cm)

**MCB:**
- `mcb_merek`: Schneider / ABB / Chint / Hager / LS / lainnya
- `mcb_ampere`: numeric
- `mcb_phase`: 1P / 2P / 3P

**Kabel:**
- `kabel_tipe`: NYM / NYA / NYY / NYFGBY / AAAC / lainnya
- `kabel_mm2`: numeric (mm²)
- `kabel_panjang`: free text (e.g. "100m/Rol", "Per Meter", "50m/Rol")

---

## Auto-generated Product Name

Computed on the frontend from spec fields. Never entered manually.

- **Panel**: `Panel {material} {tipe_pasang} {tinggi_cm}×{lebar_cm}×{tebal_cm}cm {ketebalan_mm}mm {finishing} {kelengkapan}`
  - Example: `Panel Besi Indoor 60×40×20cm 1.5mm RAL7032 Kosong`
- **MCB**: `MCB {mcb_merek} {mcb_ampere}A {mcb_phase}`
  - Example: `MCB Schneider 16A 1P`
- **Kabel**: `Kabel {kabel_tipe} {kabel_mm2}mm² {kabel_panjang}`
  - Example: `Kabel NYM 2.5mm² 100m/Rol`
- **Aksesori**: `{deskripsi}` (free text, no auto-generation)

## Frontend — StockManagerScreen

### Filter bar
- Search input: "Cari SKU atau nama barang..."
- Category dropdown: Semua Produk / Panel / MCB / Kabel / Aksesori

### Add form (replaces current form entirely)
Row 1 (4 columns):
- **SKU**: disabled field, shows "Akan dibuat otomatis oleh sistem" (italic, slate color)
- **Kategori**: required dropdown (Kabel / Panel / MCB / Aksesori)
- **Harga (Rp)**: required numeric
- **Stok (Pcs)**: required numeric

Nama Produk preview (full width):
- Auto-computed from spec fields, displayed as disabled purple field
- Caption: "Diisi otomatis dari spesifikasi — tidak bisa diedit manual"

Spec divider + dynamic spec section (based on selected Kategori):
- Panel: 4-col row (Material, Tipe Pemasangan, Ketebalan Plat, Finishing) + 4-col row (Tinggi, Lebar, Tebal, Kelengkapan)
- MCB: 3-col row (Merek, Ampere, Phase)
- Kabel: 3-col row (Tipe, mm², Panjang)
- Aksesori: 1 text field (Deskripsi)

Action buttons: Batal / + Tambahkan Produk

### Stock table rows
6-column grid per row:
1. Category label + short auto-ID (first 8 chars of UUID, formatted `#xxxx-xxx`)
2. Product name (bold) + spec pills
3. Price editable input (Rp prefix, inline)
4. Stock editable input (centered, red if < 10)
5. Status chip (✓ Sinkron / ⚠ Stok Tipis)
6. Edit button + Delete button

### Inline edit (Edit button)
Expands the row into a form with all spec fields for the row's category + price + stock. Same field set as Add form (minus SKU/name). Save / Cancel buttons inside the expanded row.

### Pill colors
- Panel specs: blue (`bg-blue-100 text-blue-900`)
- MCB specs: amber (`bg-amber-100 text-amber-900`)
- Kabel specs: emerald (`bg-emerald-100 text-emerald-900`)
- Aksesori specs: slate

## CSV Bulk Upload

### Template download
Generates a CSV with these columns (no sku, no nama_produk — both auto-generated):

```
kategori, harga, stok, material, tipe_pasang, tinggi_cm, lebar_cm, tebal_cm, ketebalan_mm, finishing, kelengkapan, mcb_merek, mcb_ampere, mcb_phase, kabel_tipe, kabel_mm2, kabel_panjang
```

Fill only the spec columns for the relevant category (leave others blank with `—`).

### Upload processing
On upload:
1. Parse CSV rows
2. For each row, build `specs` object from relevant columns (skip blank/`—` cells)
3. Auto-generate `name` from specs using the same name-generation logic
4. Auto-generate `sku` = `crypto.randomUUID().slice(0, 8)` (frontend-generated, falls back to DB default)
5. Call `upsertStock` for each row
6. Show progress + success/error toast

## Backend — Go

### `backend-go/internal/models/types.go` — StockItem

```go
type StockItem struct {
    SKU      string                 `json:"sku"`
    Name     string                 `json:"name"`
    Category string                 `json:"category"`
    Price    float64                `json:"price"`
    Stock    int                    `json:"stock"`
    Status   string                 `json:"status"`
    Specs    map[string]interface{} `json:"specs"`
}
```

### `backend-go/internal/db/stock.go` — SearchStockByName

Update query to also search spec field text:

```sql
SELECT sku, name, category, price, stock, status, specs
FROM stocks
WHERE (LOWER(name) LIKE $1 OR LOWER(specs::text) LIKE $1) AND stock > 0
ORDER BY name ASC LIMIT 10
```

Scan `specs` column into `item.Specs` using `json.Unmarshal` on a `[]byte` scan target.
